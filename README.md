# 今回の取り組みまとめ

## 工夫した点

今回のプログラムでは、超音波センサーと赤外線センサーを用いて、障害物を検知しながらコースを走行できるようにした。

特に、処理が複雑になりすぎないように状態遷移を用い、

- 行きの障害物回避
- コーナーでの旋回
- Uターン
- 帰りの障害物回避
- ゴール判定

というように、走行状況ごとに処理を分けた。

また、赤外線センサーはペットボトルだけでなく壁にも反応してしまうため、単純にセンサーが反応しただけで次の状態に進まないように判定方法を工夫した。

具体的には、状態が切り替わった直後は一定時間赤外線センサーの判定を無視し、一度センサーが非検知状態になったことを確認してから、次の検知を有効にするようにした。また、1回だけの反応ではなく、複数回連続して反応した場合に障害物を検知したと判断することで、誤検知を減らすようにした。

超音波センサーについても、一度だけ距離がしきい値以下になった場合ではなく、複数回連続して近い距離を取得した場合に壁として判断するようにした。

デバッグ時にはシリアルモニタに、

- 現在の状態
- 左右の赤外線センサーの値
- 超音波センサーで取得した距離

を表示し、どの条件で状態が遷移しているのか確認できるようにした。

## 苦労した点

最も苦労したのは、実際の走行では想定した通りの位置や向きでロボットが動かないことだった。

ロボットが完全に直進するわけではないため、少し左右にずれただけでも赤外線センサーが壁に反応し、本来とは異なる状態へ遷移してしまうことがあった。

また、Uターンやコーナーなど複数の動作が連続する場所では、旋回中に別のセンサーが反応し、その反応によって次の処理に進んでしまうこともあった。

そのため、プログラム上では正しく動作していても、実際のロボットではセンサーの位置や車体の向き、モーターの左右差なども考慮する必要があると感じた。

## 反省点

コーディングでは、当初実装したいと考えていたものとはかけ離れた動作になる場面が多く、実際に動かしながら何度も修正することになった。

特に最初は、赤外線センサーが反応した瞬間に状態を遷移させていたため、壁などへの誤反応を十分に考慮できていなかった。

また、`=` と `==` の書き間違いや、変数・関数の定義不足など基本的なミスもあり、動作確認以前にコンパイルエラーの修正に時間を使ってしまった。

さらに、旋回時間や障害物を検知する距離などを感覚的に決めている部分も多かったため、最初から実験結果をもとに数値を設定していれば、より効率よく調整できたと考える。

## 学んだこと

今回の作業を通して、センサーを使用したプログラムでは、単純に「反応した・反応していない」だけで処理を決めるのではなく、誤検知や実際の機体の動きを考慮した判定が必要であることを学んだ。

また、状態遷移を利用することで現在どの処理を行っているのか整理しやすくなる一方、状態を切り替える条件を適切に設定しなければ、想定外の遷移が発生することも分かった。

実際にロボットを動かしながら、センサー値や状態を確認して少しずつ条件を修正していくことが重要だと感じた。

## 今後の改善点

今後は、赤外線センサーだけで障害物を判断するのではなく、超音波センサーの距離情報なども組み合わせて、より正確に障害物を判定できるようにしたい。

また、左右のモーターの速度差を調整し、できるだけ直進できるようにすることで、壁への誤反応そのものを減らしたい。

旋回やUターンについても、時間だけで動きを決めるのではなく、センサーを利用して車体の位置や向きを補正できれば、より安定した走行ができると考える。

今回、当初考えていたものとは異なる形になった部分も多かったが、試行錯誤を通してプログラム全体のおおよその流れを掴むことができた。今回発生した問題とその原因もある程度把握できたため、次回はそれを踏まえて完成させたい。
